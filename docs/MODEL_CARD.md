# Model card — turbofan-surrogate

## Model details

- **Model type:** Multi layer perceptron (MLP), feed-forward, fully connected.
- **Framework:** Flax (JAX), trained with AdamW + cosine schedule.
- **Variants shipped:** `tiny` (20k params) / `small` (138k) / `default` (453k) / `large` (1.06M).
- **Inputs:** 17 dimensions = 10 dim health state + ALT + MACH + COMMAND + DTAMB + 3 dim phase one-hot.
- **Outputs:** 7 sensors (`HPC_Tout`, `HP_Nmech`, `HPC_Tin`, `LPT_Tin`, `Fuel_flow`, `HPC_Pout_st`, `LP_Nmech`).
- **Activation:** SiLU.
- **Normalisation:** per dim input/output normalisation, frozen at training time, baked into the saved artefact.
- **Loss:** MSE in normalised output space (per output unit variance).
- **Version:** 0.1.0.

## Intended use

Fast batched approximation of the ODSMR turbofan engine simulator, intended for:

- Online environment stepping in reinforcement learning loops where ODSMR's CPU latency (~280 ms / call) is a bottleneck.
- Rapid Monte Carlo over engine operating conditions (uncertainty quantification, sensitivity analysis).
- World model evaluation pipelines that need to query a ground truth thermodynamic map at high throughput.

The surrogate is **not** intended for:

- Production engineering decisions (certification, control law design, maintenance scheduling). It is an approximation of an approximation.
- Operating points outside the training envelope (see "Out of scope" below).
- Replacing the underlying ODSMR simulator in any setting where the underlying solver's guarantees matter.

## Performance

On a held out 200,000 row evaluation set drawn from the same operating distribution as training, the **default** variant achieves:

- R² ≥ 0.9998 on every sensor.
- Mean nMAE 0.55 % of natural sensor standard deviation.
- Max nMAE 1.0 % (HP_Nmech, the most state coupled output).
- Worst single sample relative error: ~2.5 % of natural sensor scale.
- 14× to 64× lower nMAE than a per context mean baseline that knows the operating point but not the health state — i.e. the model demonstrably learned state driven physics.

Per slice breakdown (per phase, per context, per wear mode, per quantile bin, in core vs extended) is in `reports/default_evaluation.md`.

## Throughput

Measured on a single NVIDIA V100 32 GB:

| Batch | Samples / sec |
|---:|---:|
| 1 | 1,127 |
| 256 | 257,499 |
| 4,096 | 2,304,138 |
| 16,384 | 3,766,311 |

For comparison, ODSMR runs at roughly 4 calls/sec on a single CPU thread, so the surrogate at large batch is over a million times faster per device.

## Training data

- 999,293 (input, sensor) pairs sampled from the TurboSens operating distribution.
- States drawn from a four mode wear mixture: pristine (20 %), mid wear (35 %), heavy wear (30 %), post action restoration (15 %).
- Contexts sampled uniformly across 16 named operating points.
- Physical inputs (ALT/MACH/COMMAND/DTAMB) jittered per sample within the documented envelope.
- All targets generated by the ODSMR simulator on Jean Zay (128 CPU nodes × 40 cores). Diverged samples (~0.06 %) dropped before training.

The training data itself is not redistributed in this package; see the companion `rl_simulator_safran` repository for the generation pipeline.

## Out of scope inputs

The training envelope is wider than ODSMR's documented "tested core" but bounded:

- ALT: 0 to 39,000 ft
- MACH: 0 to 0.84
- COMMAND: 15,000 to 125,000 lbf (only used in CR phase)
- DTAMB: -15 to +30 K
- state: per module bounds from STATE_BOUNDS

Predictions outside any of these is out of distribution. The model has no built in clamping — it will produce a number, but that number is not characterised.

## Known failure modes

Hard case analysis on the held out eval set shows the worst residuals concentrate in two regimes:

1. **Cruise (CR phase)** is over represented in the worst residuals (1.43× over its frequency). This is structural: the cruise step climb covers the most operating point variation in the dataset.
2. **post_action wear regime** is dramatically over represented (3.4× over its frequency). post_action samples are heavy wear engines with one module restored; their sensor signatures are inherently ambiguous unless action history is integrated. This is a property of the inverse problem, not a fixable bug, and is precisely the regime that makes this surrogate useful for world model evaluation.

Even in these regimes, errors stay below 2.5 % of natural sensor scale; nothing fails catastrophically.

## Ethical considerations

The surrogate approximates a research turbofan simulator. It is not certified for operational use in aviation. Users should not draw safety relevant conclusions from its predictions.
